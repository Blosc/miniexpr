# Portable miniexpr DSL profile 0.1

**Status: conservative feature boundary frozen for release preparation.**
This is the normative release subset, not the full native DSL. The native
validator, artifact authoring, and native artifact loader enforce this boundary.
Earlier broader draft artifacts may now be rejected: they were experimental,
not published compatibility promises. Platform certification is separate from
freezing the language; current local certification is macOS arm64.
Windows release conformance targets the interpreter baseline; enabling a TCC
build option there is not yet a Windows JIT certification claim.
Wasm32 `int()` kernels conservatively use the interpreter: the current JIT source
adapter implements 32-bit casts and cannot preserve the full int64 value domain.

## Signatures and binding

- One top-level named `def`, with unique plain positional parameter names.
- Explicit `bool`, `int32`, `int64`, `float32`, or `float64` signatures; all
  parameters, including typed constants/captures, share one dtype. Output may
  differ. No automatic, complex, string, or mixed-input signatures.
- Binding is by name, with exactly one binding per parameter. Descriptors are
  metadata (`ME_VARIABLE`, NULL address/context, itemsize zero), not callbacks.
- Each element produces one output independently. No reductions, ND/index/shape
  symbols, arrays inside source, external functions, implicit globals, or `print`.
- Supported native comments, docstrings, numeric-literal normalization, and
  compiler pragmas do not introduce Python execution or a second language parser.

## Statements and expressions

Assignments, expression statements, `return`, `if`/`elif`/`else`, `pass`, bounded
`for ... in range(...)`, `while`, `break`, `continue`, and native augmented
assignment are admitted. Locals must be initialized on every executed read path.

Expressions admit finite numeric literals, unary `+`/`-`, `+`, `-`, `*`, numeric
comparisons, native chained comparisons, and Boolean `and`/`or`/`not` (`!`).
Chains evaluate operands left-to-right, at most once, skipping later operands
after failure. Logic returns Boolean results, not Python's operand-return values.

Floating division is admitted only with supported floating computation; integer
division and division inside comparison/logical predicates are excluded.
`range` is admitted only in a for header. Powers, remainder, bitwise operators,
indexing, attributes, and strings are excluded.

`int()` and `float()` accept only a leaf name or numeric literal. `float()` on
integral-input signatures is excluded; use explicit output conversion instead.
For floating-input signatures, `bool()` also accepts only a leaf. In Boolean
numeric contexts `bool()` may consume supported arithmetic. Every other call,
including `sin`/`cos`, is excluded. Tested transcendental and nested-cast native
implementations remain available in the full DSL, not portable 0.1.

The compiled-tree gate rejects arithmetic with differing arithmetic-intermediate
computation dtypes, integral variables implicitly entering floating arithmetic,
and differing numeric-cast intermediates (Boolean zero/one casts are allowed).
Float32 arithmetic nested inside a comparison/logical predicate is excluded;
use a separately assigned, rounded local followed by a comparison. These checks
apply in all branches and loops, including currently inactive paths.

## Numeric semantics and domains

- Integer transport, identity, and comparisons preserve exact values, including
  int64 values beyond `2**53`. Integral-input literal magnitudes are limited to
  `2**53`; pass wider values as typed inputs/constants. Integer intermediates
  must remain representable in their computation dtype.
  Integral-input signatures accept only integer-spelled literals; decimal-point
  and exponent spellings are excluded, including inside comparisons/casts.
- Homogeneous floating arithmetic rounds scalar constants and each arithmetic
  intermediate in the compiled computation dtype. Float32 pure arithmetic and
  same-dtype leaf `float()` use typed JIT lowering. Floating literals are
  contextual: float32 input with float64 output can compute in float64, rather
  than compute in float32 and merely widen the final value.
- Boolean operands are numeric zero/one during arithmetic. Boolean-only and
  integral-valued-literal contexts compute in int64; fractional-literal contexts
  compute in float64. Preserve numeric intermediates and locals until an explicit
  `bool()` or final Boolean output performs nonzero truth conversion.
- `bool()`/Boolean output use nonzero truth, including NaNs and infinities;
  both signed zeros are false. `int()` consumes its argument before truncation
  toward zero. Integral identity casts do not round through double.
- Explicit output conversions are supported on representable values: exact
  integer identity/widening, representable narrowing, floating widening/narrowing,
  integer-to-floating nearest-even rounding under the default rounding mode,
  finite representable float-to-integer truncation, and nonzero truth.
- Floating identity preserves zero sign and non-finite classification/sign.
  NaN payloads are not promised. Strict arithmetic excludes reassociation/FMA;
  floating overflow/non-finite arithmetic follows the linked IEEE/libm behavior
  only in certified contexts, not a global transcendental accuracy guarantee.

**Runtime-domain exclusions:** signed integer overflow, out-of-range narrowing,
non-finite/out-of-range float-to-integer casts, zero divisors, invalid/unrepresentable
range bounds, and non-default floating rounding modes are outside the contract.
No wrapping, trapping, or deterministic output is promised for them. Static
validation cannot prove data-dependent domains; callers must satisfy these
preconditions. This is not a memory-safety sandbox for adversarial source/data.

## Execution policy and errors

The interpreter is the baseline. TCC/CC are optional accelerators, with
conservative fallback when code generation is unavailable. Explicit
`# me:compiler=tcc|cc` overrides compiler defaults, not `ME_JIT_OFF`.
Portable FP semantics are strict: absent or explicit `# me:fp=strict` is admitted;
non-strict source modes are rejected. The artifact loader injects strict mode
into an internal compilation copy when absent, independent of host defaults.
Raw-source callers must select strict execution themselves.

Missing return on an executed path, zero range step, and while-cap exhaustion
report `ME_EVAL_ERR_INVALID_ARG`. Semantic JIT errors must not rerun a kernel in
the interpreter; failed output contents are unspecified. Incomplete return
coverage may compile; unexecuted missing paths do not fail evaluation.

`ME_DSL_WHILE_MAX_ITERS` defaults to 10,000,000 body entries per loop invocation.
Positive values cap execution, nonpositive values disable it, and invalid values
use the configured default. Test the condition before the cap. `continue` counts
as an entry; `break`/`return` on the final allowed entry succeeds. Nested/re-entered
loops have independent counters; lowered condition prefixes are not body entries.
JIT cap policy participates in cache identity. A changed policy after loading
selects interpreter execution under the current policy.

Empty artifact evaluations validate bindings but do not execute the kernel.
Artifact versions, exact constant encodings, bounded broadcasting, ownership,
and import diagnostics are specified in [artifact-0.1.md](artifact-0.1.md).

## Validation and certification

`me_validate_portable_dsl(source, "0.1", inputs, ninputs, output_dtype, error)`
checks signature, source features, native compilation, and compiled expression
membership without execution or JIT. Success clears optional diagnostics.
Failures distinguish unsupported version, invalid signature/source, unsupported
feature, and allocation failure, with source locations where available.
Parsing/compilation require trusted or isolated input; bounded bookkeeping is
not general resource isolation.

The shared corpus is in `tests/portable-dsl/`. `frozen-excluded.txt` distinguishes
retained full-language regressions from release conformance; each excluded case
has a negative portable validation test. Python tests additionally verify native
import rejects excluded source even when the authoring path is bypassed.
Exact tests check integer/Boolean values, floating rounding boundaries, zero
signs, and non-finite classification. Certification does not mean all arbitrary
input data satisfy the runtime-domain preconditions.

Scope is closed for 0.1. Broader math, nested casts, mixed-intermediate promotion,
overflow policy, lazy/container integration, and further optimizations belong
to a later profile. Remaining release gates are packaging and platform CI, not
additional numeric feature expansion. The [audit history](numeric-audit-0.1.md)
records corrections and limitations; the [full DSL reference](../dsl-syntax.md)
is not normative beyond this explicitly frozen subset.
