# Menudet 1.0 — language draft

**Menudet — a little language for portable computation on arrays and tables.**

Menudet names the portable language, while miniexpr is its native implementation.
Existing DSL API names and artifact format identifiers remain unchanged; this
name does not change versioned execution semantics.

Status: normative implementation draft, accepted by typed core source validation
and the optional native artifact loader in development builds. Rules below
describe the implemented versioned path, not
certification of every release platform. Public freeze follows beta feedback.

## Execution model

One function processes a host-supplied evaluation block in a declared logical
domain. Inputs are immutable named typed values. Results are either elementwise
or one scalar per block; return paths must have consistent cardinality.
The interpreter is normative. Optional JIT must preserve semantics or fall back
before execution. Required-JIT may reject unavailable acceleration. Evaluation
failure is never retried as success using a different backend.

No callbacks/closures, complex computation, print/effects, non-strict FP modes,
opaque objects, arbitrary memory access, or dynamically sized intermediates.
Supported host authoring conveniences must normalize before native validation.

## Types and intermediate computation

Types are bool; int8/16/32/64; uint8/16/32/64; float32/64; fixed-width Unicode
code units; fixed-width bytes. Arithmetic excludes strings except the explicitly
enumerated string operations. See `features-1.0.json` for the finite draft matrix.

Operand types determine intermediate types; output conversion is last.
Homogeneous integers/floats retain their type. Boolean arithmetic promotes
Boolean operands to int64 zero/one, including the context used for an accompanying
weak arithmetic literal. Boolean logical operations produce bool.
Same-signedness integers promote to the wider operand. Mixed signed/unsigned
integers promote to the smallest signed type covering both complete ranges;
reject if no supported integer type covers them. float64 dominates float32;
integer/float32 arithmetic stays float32 only for integers of at most 16 bits,
otherwise promotes to float64. Floating conversion may lose integer precision.

Weak source literals adapt to a compatible typed companion where in range;
a fractional floating literal with an integer/Boolean companion remains a
floating operand, rather than being truncated to an integer. Decimal floating
literals round once, nearest/ties-even, to the selected float type; `0.1` need
not be exactly representable. Contextually out-of-range literals require an
explicit conversion or typed constant. Literal-only integers default to int64,
floats to float64. Captured typed constants are strong operands.

Integer `/` produces float64; float32/float32 `/` produces float32. Each float32
operation rounds to float32 before the next operation, independently of output.
`int` evaluates the argument then truncates toward zero to int64; `float`
converts to float64; `bool` converts numeric zero to false and nonzero, including
NaN, to true. Boolean output does not change numeric intermediate computation.
Mixed integer comparisons must be exact, without conversion through double.

Integer overflow and out-of-range narrowing are errors, including intermediate
arithmetic and accumulator operations. Integer floor division/modulo by zero,
invalid shifts, and non-finite/out-of-range float-to-integer conversion are errors.
No C undefined behavior or accidental wrapping is a language guarantee.
Floor division rounds toward negative infinity; modulo has the divisor's sign.
Integral powers require a nonnegative exponent and check each multiplication;
`0 ** 0` is one. For negative powers use an explicit floating operand. Left
shift is checked multiplication by a power of two (including negative operands);
signed right shift is floor division by that power. Counts must be between zero
and one less than the operand width. Integer bitwise results use fixed-width
two's-complement interpretation without depending on C signed narrowing.
Floating arithmetic preserves IEEE NaNs, infinities and signed zero, including
division by zero. Implicit contraction/reassociation is forbidden; explicit fma
is a separate admitted operation. Transcendental bitwise equality is not promised.

`~` is admitted for integral/Boolean operands: fixed-width two's-complement
complement for signed integers, width-masked complement for unsigned integers,
and Boolean inversion for bool. Floating operands reject at validation.
`ceil`/`floor` round toward positive/negative infinity, `trunc` toward zero,
`rint` nearest with ties to even, and `round` nearest with ties away from zero.
These retain floating dtype and signed zero; integral operands are identities
(Boolean arithmetic maps to int64). `abs` on a signed minimum is an overflow
error; unsigned abs is identity. `square` checks integral multiplication, and
`sign` preserves floating signed zero/NaN and maps other values to signed one.

`fac(n)` has exactly one integral operand; `ncr(n,k)`/`npr(n,k)` have exactly two.
Require n >= 0 and 0 <= k <= n; 0! and a zero-length selection are one. Factorial
retains its integer dtype (bool maps to int64); binary combinatorics use the
common integer promotion. Every product/conversion is checked, with cancellation
before multiplication for binomial coefficients. Factorial's largest admitted
n by result dtype is 5 for int8/uint8, 7 for int16, 8 for uint16, 12 for
int32/uint32, 20 for int64/uint64; a Boolean operand can only supply 0 or 1.
For ncr/npr, the exact result and checked intermediates must fit the result type;
there is no value-dependent floating fallback or fixed blanket n limit.

The finite function matrix in `features-1.0.json` supplies exact arities, typed
signatures, domains and IEEE special cases. Unary transcendental functions yield
float32 for float32 inputs and float64 for integral/Boolean/float64 inputs.
Floating binary math uses the common numeric type: float32 remains float32,
otherwise float64, and an unsupported arithmetic join (e.g. int64/uint64)
rejects rather than guessing from operand values. Domain exceptions return the
documented NaN/infinity, not unchecked integer conversions. NaN payloads are
unspecified. `fmin`/`fmax` ignore one NaN, return NaN for two; on zero ties fmin
is negative if either zero is negative, fmax only if both are negative. They
are per-lane operations, unlike NaN-propagating block min/max. `fmod` uses a
truncated quotient; `remainder` uses the nearest quotient with ties to even.
`nextafter` steps in the selected floating format; equality returns the second
operand, including signed zero. Explicit fma has one rounding, not two.

No global cross-platform ULP bound is promised for the underlying C99 libm
functions, gamma, general powers or non-anchor pi-scaled trigonometry. Independent
function-specific accuracy is a **pending release gate**, not an inferred
guarantee from one host's libm. Exact constants `pi()` and `e()` have binary64
bits 0x400921fb54442d18 and 0x4005bf0a8b145769 respectively.

Checks apply only to participating lanes and selected short-circuit/where
branches. Failures propagate to the host; native output after failure is
unspecified and cannot be returned or cached as a successful result.

## Limited block reductions

Top-level reduction values and supported reduction conditions are admitted.
Reduction assignments/returns inside control-flow bodies remain excluded.
An `if all(...)` condition inside a loop is admitted, including Mandelbrot early
exit. Scalar reduction operands broadcast only to participating lanes.

The reduction group is the valid, currently participating block lanes in logical
C-order. Exclude padding and lanes removed by return/break. Continue removes a
lane for the remainder of its iteration, not subsequent iterations. Nested
conditions reduce over their entry mask, not all physical block slots.

`any(empty)=false`, `all(empty)=true`, `sum(empty)=0`. Empty min/max errors.
`prod(empty)=1` and `mean(empty)=NaN`. Signed/Boolean sum and product accumulate in
int64; unsigned in uint64. Floating sum/product retain the input floating type,
rounding at every ordered accumulation step. Integer mean uses the checked ordered
integer sum followed by float64 conversion/division; floating mean uses its input
type for both the ordered sum and final division. Numeric reductions propagate NaNs.
For mixed signed-zero ties min chooses negative zero and max chooses positive
zero; same-sign zero ties retain that sign. Truth
reductions treat NaNs as true, like bool conversion. These rules still require
external platform execution of the local mask/empty/cardinality corpus before
release certification.
Floating sums have a specified sequential logical order, not an arbitrary
parallel tree. Integer accumulation is checked at every step.

Elementwise returns such as `x - mean(x)` have the original block extent;
`return mean(x)` has block-scalar cardinality. A scalar used in an elementwise
calculation does not imply scalar return cardinality.

Persist logical evaluation partitions independently of storage chunks.
Rechunking cannot silently alter groups. Partial elementwise reads evaluate
original groups then select lanes. Explicit repartitioning may change results.
Block-scalar outputs have block-grid shape and row-major block ordering.

A block-scalar return must be reached coherently by its original group. Reduced
locals do not permit lane-varying conditions to select among scalar return sites.
The typed validator conservatively rejects scalar returns inside lane-varying
branches/loops, or inside a loop with lane-varying break/continue. This is an
ambiguous-output diagnostic, even if two such return expressions happen to match;
no first/last-lane selection or cardinality reinterpretation occurs. Uniform
reduced-scalar conditions and coherent scalar loops remain supported. Varying
loops may rejoin before a single top-level scalar return.

## ND context and strings

Hosts supply logical shape and block origin/extent. `_flat_idx` is the C-order
index in the declared domain; `_i<d>` is a coordinate and `_n<d>` its logical
dimension size; `_ndim` is rank. Padding is not part of that domain. Input
broadcasting does not change the output coordinate domain. Slicing an existing
saved kernel retains its coordinates/groups; defining a kernel on a view uses
that new kernel's declared domain.

Unicode and bytes remain separate fixed-width types. Preserve first-NUL value
termination, full-width values without a terminator, statically inferred width
bounds and case-expansion truncation. Case mappings are pinned to the bundled
**Unicode 15.0.0** table, independent of the host's Python/Unicode version or
locale. Unicode stripping uses exactly U+0009–000D, U+0020, U+001C–001F,
U+0085, U+00A0, U+1680, U+2000–200A, U+2028–2029, U+202F, U+205F and U+3000.
Bytes stripping uses only 09–0D and 20; byte case conversion is ASCII-only.
Valid logical Unicode characters are scalar codepoints, with no normalization;
comparison is lexicographic codepoint order, bytes comparison unsigned octet
order. Input characters after first NUL and invalid padded lanes are not text.
Captured Unicode constants validate their full encoded slots. Source literals
used with byte operands must be ASCII; captured byte constants/buffers may contain
arbitrary octets. Direct string truth conversion is logical nonemptiness; direct
string reductions are excluded (reduce a Boolean predicate instead).

All intermediate/output string slots are positive and at most 1 MiB; Unicode
slots are multiples of four bytes. Concatenation sums widths, alternative/local
joins take maximum width, and case conversion retains width, truncating expansions
to that width. `substr(s,start,length)` admits integral dynamic indices: negative
start counts from logical end then clamps to zero; start past end or negative
length gives empty, otherwise clip to the available suffix. `split_part(s,sep,k)`
uses only the first separator; k <= 0 is head, k > 0 the remainder. A missing
separator gives the whole head or empty remainder. `replace` performs left-to-right
nonoverlapping matches with checked static growth bounds; empty literal needles
reject during compilation and empty runtime needles error. String output buffer width is a
native inference result, not a NumPy result-type estimate. Host varlen packing
does not introduce a varlen intermediate language type.

## Validation and persistence

Validate source, resolved functions, inferred types/effects/cardinality and
capabilities without execution. Artifacts declare versions, requirements,
signatures and exact typed constants. Hosts bind context and data explicitly;
unsupported capabilities or malformed descriptors fail before execution.
Import must not reconstruct or execute Python source.

Core `me_validate_portable_dsl(..., "1.0", ...)` dispatches to typed profile
compilation with JIT off, numeric output width, rank zero and inferred cardinality.
`me_validate_portable_dsl_ex` additionally accepts a versioned, size-checked
descriptor with exact string output itemsize, logical ndim and optional asserted
elementwise/block-scalar cardinality. String input widths are carried on plain
`me_variable.itemsize`; no data pointers, callbacks or mutable context are allowed.
Missing/insufficient ND rank, invalid string widths, mismatched return contracts,
unsupported effects and mixed computations reject before execution. Diagnostics
retain native status and source line/column where relevant (zero for signature
context errors). The API belongs to the core library and does not require yyjson
or the optional artifact loader. Only draft version 1.0 is supported.

For example, core-only C validation needs no arrays or JSON:

```c
me_variable input = {.name = "x", .dtype = ME_INT16, .type = ME_VARIABLE};
me_portable_validation_descriptor context = {
    .struct_size = sizeof(context),
    .version = ME_PORTABLE_DSL_VALIDATION_DESCRIPTOR_VERSION,
    .ndim = 1, .cardinality = ME_PORTABLE_ELEMENTWISE
};
me_portable_error error;
me_portable_status rc = me_validate_portable_dsl_ex(
    "def coordinate(x):\n    return x + _i0\n", "1.0",
    &input, 1, ME_INT64, &context, &error);
/* rc == ME_PORTABLE_SUCCESS; no evaluation or JIT was performed. */
```

Validation does not create an executable handle or switch the semantics of an
ordinary full-profile compiler invocation. Portable execution must use a handle
compiled for the versioned profile (for example the extended artifact API).

New persisted DSL kernels must pass 1.0 validation after normalization. No
Python-source fallback. Detect legacy formats from metadata and require explicit
user opt-in (`deserialize="full"` in Python); propagate policy through nested
opens. No migration tooling or automatic conversion. The standalone contract
does not promise support for every host storage or remote-access protocol.

## Local implementation closure versus release gates

Per-operation arities/types, joins, checked powers/bitwise rules, math domains,
tie/NaN/zero rules, reductions, fixed encodings and Unicode data are specified
above and in the finite JSON matrix. Logical rank is 0–8; reserved ND symbols
require a positive covering rank, regardless of physical storage dimensions.
Core public source validation and optional artifact validation both use typed
profile compilation. Independent analytic/reference
fixtures below supplement the same-host libm regression matrix. Remaining gates
are target-platform execution, independent function-specific accuracy bounds,
published-pin/stock-wheel integration and public draft feedback—not unspecified
local arities or an unimplemented 1.0 validation dispatch.

## Versioned typed implementation (draft, not release-certified)

The internal profile-aware compiler now preserves weak literals and exact integer
magnitudes in the existing parser's expression tree, inserts typed checked
conversions, and uses the existing masked statement interpreter. It skips
full-DSL optimization/output-context promotion and all JIT preparation/execution.
Core checked arithmetic, casts/comparisons, lazy truth/where, a libm subset and
ordered masked reduction nodes have native integration tests. Portable `log`
binds natural logarithm even when the full language's `log` is configured as log10.
`rint` has nearest/ties-even semantics independent of ambient rounding mode;
`round` retains the native half-away-from-zero rule.

The staged strict interpreter saves the calling thread's floating-point
environment during compilation and expression evaluation, selects and verifies
nearest/ties-even with nontrapping exceptions, and restores the original rounding
mode and exception flags on every exit. It verifies gradual underflow for float32
and float64; a caller environment that flushes subnormals is rejected rather than
silently changing the contract. No process-global policy switch is used.

Local reads carry evaluation-local per-lane definition state. Reading an
uninitialized local in a participating lane errors, including inside a reduction;
a discarded lazy operand or invalid padded lane does not read that local.
Range bounds use checked conversion to int64 (finite floats truncate toward zero),
rejecting non-finite/out-of-range values before the legacy loop executor runs.

`sinpi` and `cospi` reduce the input modulo two in units of pi before multiplying
by pi, reflecting fractional arguments into [0, 1/4]. Integral/half-integral
anchors are exact even for large representable inputs. Integral `sinpi(x)` is
zero with the sign of x; half-integral `cospi(x)` is positive zero. Non-finite
inputs yield NaN. This avoids losing the fractional part in a large intermediate
radian argument; general libm accuracy still requires platform certification.

### Finite independent reference fixtures

`independent_anchor_fixture` covers canonical unary functions and aliases at
analytically known values (zero, unit, perfect squares/cubes, exact integer
logarithms and gamma factorials), round/rint/trunc tie and signed-zero anchors,
and per-lane binary functions at exact or independently rounded constants.
`logaddexp(0,0)` uses the precomputed correctly rounded ln(2) hexadecimal value,
not a runtime call to the implementation's libm. `atan2(0,-1)` uses independent
pi bits. `nextafter(1,2)` is checked against the adjacent-format hexadecimal
encoding. Explicit fma evaluates `(1+2^-p)*(1-2^-p)-1` against exactly `-2^-2p`
with p=23/52, demonstrating fused single rounding. pi/e are checked by exact
binary64 constants, and integral bitwise complement/factorial use exact values
and explicit overflow/domain errors. Binary NaN/infinity/zero cases exercise
fmin/fmax, copysign, fdim, hypot, fmod, remainder, nextafter and logaddexp.

These fixtures run for float32/float64; zero/bit-step/fused/constant anchors are
exact, other analytic/nonzero references use an explicit 8-epsilon relative
**regression** criterion. That bound is not a new release accuracy guarantee.
Existing combinatoric fixtures also cover exact 67 choose 33, large uint64
permutations and checked overflow; reduction fixtures cover ordered cancellation,
empty/NaN/zero semantics and the original participating masks.

### Executed finite host math matrix (additional regression gate)

Python-Blosc2 additionally maintains an independent finite certification corpus
in `scripts/menudet_math_vectors.json`, checked by
`scripts/certify_menudet_math.py`. It contains 284 float32/float64 samples for
40 canonical operations, generated with mpmath at 100 and 200 decimal digits
and requiring agreement after rounding. Execution uses the native artifact
loader/interpreter, not Python evaluation of the kernel. Exact input/reference
encodings and per-function sample budgets are checked in; no reference library
is required at runtime. The corpus runs in native Python, WASM and wheel CI.
Its finite-domain budgets are not normative universal libm error bounds. Native
exceptional-value, alias, rounding and exact-anchor fixtures remain required.
Cross-platform certification remains pending until those Python runs pass.

`test_dsl_portable_interp.c::operation_domain_fixture` compiles each operation
for both float32 and float64, checks its native result dtype, and evaluates:

| Operations | Valid representative input | Reference/result bound |
| --- | --- | --- |
| sin, cos, tan, asin, acos, atan | 0.5 | host double libm, 8 eps relative |
| sinh, cosh, tanh, asinh, atanh | 0.5 | host double libm, 8 eps relative |
| acosh | 1.5 | host double libm, 8 eps relative |
| exp, exp2, expm1, log, log2, log10, log1p | 0.5 | host double libm, 8 eps relative |
| sqrt, erf, erfc | 0.5 | host double libm, 8 eps relative |
| cbrt, abs, ceil, floor | -0.5 | host double libm, 8 eps relative |

Here eps is FLT_EPSILON or DBL_EPSILON according to the native result type;
the executed absolute bound is `8 * eps * max(abs(reference), DBL_MIN)`.
This is explicitly a same-host precision/dispatch regression bound, **not** a
universal eight-ULP accuracy promise or an independent mathematical oracle.
Additional exact anchors, signed-zero, range-reduction, rounding, masked lanes,
overflow/conversion and ordered-reduction fixtures remain in the checked/type/
interpreter/artifact tests. The exceptional-domain matrix supplies -2 to sqrt,
log, acos, asin, acosh and atanh and requires NaN for both floating types.
Release certification must execute the same corpus on each target and separately
verify the function-specific platform accuracy requirements; a local macOS run
does not certify Windows, Linux or WASM.

The source validator and artifact loader admit draft
1.0 only after typed interpreter compilation and signature/capability checks.
Static numeric/string-width joins, masked lazy operands, scalar/empty evaluation,
fixed-string kernels and explicit ND descriptors are connected. Python logical
scheduling, partial reads/rechunking, portable persistence and independent native
table rows are connected in development builds. Remaining gates include the
independent platform/domain/tolerance matrix and stock published-pin integration.
Typed dynamic string indices and checked replacement width bounds
are implemented; required JIT rejects explicitly. The staged
acceptance is not full beta certification or a reduction of approved scope.
